# Round 2 · Phase 5 — decisions (voice + accessibility)

D-entries in docs/DECISIONS.md style, numbered D-phase5-N for the lead to renumber. Every fallback and judgment call in this workstream, with what was actually measured.

**D-phase5-1 · Chart text alternatives come from the option itself, once, in one library (team, 28 Aug 2026).**
`client/src/lib/chartA11y.js` turns any ECharts option into three things: the `aria` component (`aria.enabled` → `role="img"` and a description on the canvas container), decal pattern fills only when two or more bar/pie series are separated by colour alone (WCAG 1.4.1 — a single series or a line chart gets none, so the plots stay clean), and a `{columns, rows}` table for the "Table view" toggle and the print stylesheet (WCAG 1.1.1). The description is composed on our side from the i18n dictionary because ECharts' own generated label is English-only; a Kannada UI reads "ಬಾರ್ ಚಾರ್ಟ್ … 12 ವರ್ಗಗಳು …". Wired into ChartPanel, DashChart, ChartBody and CopilotChart, so every one of the app's ECharts surfaces carries the same alternative. An option that already carries `aria` is returned untouched, so a route can opt out or specialise. Why one library: 40-odd chart call sites; per-route table markup would drift the first week. Verified: `client/test/a11y/units.mjs` (27 checks, 27 pass) covers category, pie, heatmap, radar, gauge and `[x, y]` shapes plus the decal rule; the axe `role-img-alt` / `image-alt` rules pass on every route in run 3.

**D-phase5-3 · The axe gate fails only on serious/critical, re-audits before it fails, and excuses nothing without an in-page check (team, 28 Aug 2026).**
`client/test/a11y/axe.mjs` runs axe-core 4 with the `wcag2a wcag2aa wcag21a wcag21aa wcag22aa` tags (no `best-practice` — advisory, not conformance) and `target-size` explicitly enabled, over the static-demo build in headless Chromium, 17 routes × dark and light. Run 1 (first pass after wiring, 22 audits — the tier routes were not in the build yet): minor 6 · moderate 22 · serious 84 · critical 0. The 84 were one `aria-prohibited-attr` per audit (the toast viewport carried `aria-label` without a role), 60 `target-size` nodes (GeoIntel's 2-px month bars ×13 and the Reports section-reorder arrows ×17, per theme) and 2 colour-contrast nodes (the light About teal badge, D-phase5-2, and a dashboard shift tile caught mid-skeleton); the 22 moderate were the disclaimer strip outside any landmark; the 6 minor were empty selection-column headers on /cases and /network. Run 3 (final, 32 audits including /beat /station /state /ingest /alerts/digest, /identify not built yet): minor 0 · moderate 0 · serious 0 · critical 0, 1 248 rule passes summed. Two guards keep that honest: a route that errors or shows a serious finding is audited a second time with a 4 s settle and only findings present in both runs count (the shift-tile contrast was a transient skeleton state at 1.8 s and is absent at 2.5 s and 4 s), and the only excusal mechanism is WCAG 2.5.8's own "Equivalent" exception — a small target may declare `data-a11y-equivalent="<id>"`, and the gate looks that element up in the page and checks it is ≥ 24 × 24 px before dropping the finding (the month slider, given `h-6` = 24 px, is the equivalent of the histogram bars). No rule is disabled. The one selector allow-list entry (Leaflet / Cytoscape scrollable panes) matched zero nodes in all three runs and is kept only because the keyboard-map item (row 134) is phase 9's. The `a11y` job in `.github/workflows/pages.yml` needs `test` and the deploy now needs `[test, a11y]`, which is the plan's "a red gate blocks the Pages deploy" rule applied to accessibility; the cost is ~3 min of CI and a Chromium download per run.

*Amended 29 Aug 2026 — the gate was measuring one viewport, and it was serving the wrong build.* `auditRoute` hardcoded 1280 × 900, so the entire phone layout — a different tree, with the bottom tab bar, the More sheet, stacked cards and much narrower scrollers — was never audited; the only 360-px pass was the text-spacing probe, which runs no axe rules. The run now loops both viewports (1280 × 900, and 360 × 640 with `isMobile`/`hasTouch` so Chromium reports a coarse pointer, which is what 2.5.8 is written for): 17 routes × 2 themes × 2 viewports = 68 audits, selectable with `--viewport desktop|mobile|both`. `startPreview` also spawned `vite preview` with no `--outDir`, so it always served `client/dist` however the script was invoked; it now serves the directory `--dist` names, which is how a second build can be audited without disturbing the CI one. What the phone pass then found, all of it invisible before: 14 serious nodes on the first sweep — the dashboard heat-calendar month buttons at 20 × 24 (9 nodes), and one unreachable scrolling box each on the dashboard seasonality grid, /reports, /station and /state (the /state one fires at 1280 too, so the desktop pass had been missing it as well — the earlier "0 serious" runs pre-date the tier data rendering in the demo snapshot). Fixed rather than excused, one by one, until a full 68-audit sweep held: see D-phase5-13. The allow-list is still the single Leaflet/Cytoscape entry and it still matches zero nodes.

**D-phase5-4 · Read-aloud goes where a sentence exists, the brief's control stays out of the printed document, and the tier homes get a drop-in (team, 28 Aug 2026; extends D-014).**
`ReadAloudButton` is mounted on the alert card narrative, the FIR narrative panel header and the dashboard ticker (which reads every insight, i.e. the executive summary, in order); the Reports "Listen" control sits in the builder next to the word count and reads `execText`, deliberately not inside `BriefContent`, because that markup is also the SmartBrowz PDF target and a speaker button in an official document is wrong even with `no-print`. The tier homes are phase 4's files, so they get `ReadPageButton` instead of an edit from this workstream: `<ReadPageButton targetId="beat-home" />` (or `text={() => sentence}`) reads the visible prose of that subtree in DOM order, and a dense table is fenced off with `data-no-read`. The hide rule is unchanged from D-014 and now lives in one place (`lib/voice.js pickVoice`): under ಕನ್ನಡ only a `kn-*` voice qualifies and the control renders nothing otherwise; `useReadAloud` and `ReadPageButton` both subscribe to `voiceschanged` because Chromium answers `getVoices()` with `[]` on the first call. Not verified in this run: an actual Kannada voice — the Windows box used for the audit has none installed, so the Kannada path was exercised only through `pickVoice` in the unit checks (returns null → hidden) and English through en-IN.

**D-phase5-5 · The global microphone is a navigation, not a second copilot (team, 28 Aug 2026).**
`VoiceAskButton` reuses `useSpeechInput` (one-shot recognition in the UI language) and navigates to `/copilot?q=<transcript>` carrying the filter search string; Copilot already auto-asks a `?q=` it has not seen, so nothing was added to the copilot route. It renders nothing without `SpeechRecognition` (Firefox) and on `/copilot`, which owns its own mic. Placement: the topbar at sm+ (44 × 44 px) and a labelled 48-px row at the top of the More-sheet navigation on phones, where the topbar has no room. Kannada recognition (`kn-IN`) depends on the browser's speech service — Chromium routes it through Google's service on desktop, which is the browser's own behaviour and outside our bundle; the button is still hidden, not degraded, when the API is absent.

**D-phase5-6 · Titles and focus are owned by one shell component; only the two detail routes register their own (team, 28 Aug 2026, corrected 29 Aug).**
`ShellA11y` (mounted once in Layout) sets `document.title` from a route-registered title when one exists (`useDocumentTitle` in `lib/a11y.js`) and from Layout's nav table otherwise, prefixing the pending-alert count in one place. The first version of this entry justified the registry with "the tier homes and the face / ingest routes are not in the nav table" — that is false: `/beat`, `/station`, `/state`, `/identify` and `/ingest` all have `NAV_GROUPS` entries, so `viewKeyFor` names them and their measured titles were already correct through the fallback. The registry had no callers at all, which made it dead code. It earns its place on the two routes the nav table genuinely cannot name: `/cases/:id` is only ever "FIR detail" and `/offenders/:key` only ever "Offender 360", so CaseDetail registers `a11y.title.case` (the CrimeNo) and Offender360 registers `a11y.title.offender` (the person). Both previously assigned `document.title` directly, which is worse than useless here — ShellA11y's title effect has no dependency array, runs after every render of the shell, and overwrites the route's assignment as soon as anything re-renders. Routes still setting it directly (`Cases.jsx`, `Identify.jsx`, `Ingest.jsx`, `PrintBrief.jsx`) have the same race and belong to other workstreams. After every navigation it moves focus to `#main-content h1` (adding `tabindex="-1"` if needed), polling up to ~90 frames for the lazy chunk and skipping when the user has already focused something outside the nav; it does nothing on first paint so the skip link stays the first Tab stop. `<html lang>` already followed the UI language (`lib/i18n.jsx`, pre-painted by index.html) — verified, no change needed.

**D-phase5-7 · Live announcements are few, polite and shared (team, 28 Aug 2026).**
`announce()` writes into one of two sr-only regions (polite `status`, assertive `alert`) after clearing them so an identical message is read again — verified 29 Aug against `lib/a11y.js`: the region's `textContent` is set to `''` synchronously and the message written on the next animation frame, which is what makes a repeat re-announce. One bug found while verifying and fixed: the pending frame handle was a single module-level variable shared by both regions, so a polite message and an assertive one raised in the same frame cancelled each other — the first region was left cleared and its message never written. The handle is now per region. Wired at three shared points rather than per route: the FilterBar announces the human filter summary ("Filters applied: Bengaluru City · Last 30 days") or "Filters cleared" on change (skipping mount), DataTable announces "N rows loaded" / "No rows match" when a load finishes, and the route ErrorBoundary announces the error assertively. Toasts already had their own live viewport. Why not more: two regions firing on every panel refresh would drown a screen reader on the dashboard; a route that needs a specific message calls `announce()` itself.

**D-phase5-8 · Text-spacing and 200 % at 360 px: measured, two pre-existing overflows named, nothing gated (team, 28 Aug 2026).**
The gate's informational pass loads each route at 360 × 640 in Kannada with the Large text size and then injects the WCAG 1.4.12 overrides (line-height 1.5, letter-spacing 0.12 em, word-spacing 0.16 em, paragraph spacing 2 em) and counts visible elements whose box runs past the viewport (scrollWidth is not used: the invisible `.tt::after` tooltips legitimately widen it, which is why a first draft reported every route as overflowing). **D-phase5-9 · Text size is a root-size step, and bracketed pixel sizes deliberately do not follow it (team, 28 Aug 2026).**
`html[data-fontsize='large']` sets the root to 112.5 %, which scales every rem-based utility; Tailwind's `text-[10px]` / `text-[11px]` captions stay put. WCAG 1.4.4 (200 %) is met by browser zoom, which the audit exercises; the control is the one-tap step an officer on a shared station PC actually uses. It sits in the More sheet and the command palette ("Larger text" / "Normal text size"), persists as `dappa-fontsize`, and index.html pre-paints it so there is no jump on reload.

**D-phase5-13 · Every scrolling box is keyboard-operable, and the fix is `tabindex` + a named region, not an allow-list entry (team, 29 Aug 2026).**
A box with `overflow: auto` that holds nothing focusable cannot be scrolled by keyboard at all — Tab never lands in it and the arrow keys go to the page. axe calls this `scrollable-region-focusable` (serious, WCAG 2.1.1), and once the gate started auditing 360 px it fired on ten surfaces: the /state unit × head matrix (which fires at 1280 too — measured `scrollWidth` 1454 against `clientWidth` 974, nothing focusable inside), the Reports A4 brief preview, the dashboard seasonality day × hour grid, the Predict horizon and backtest tables, the depth heat matrices (the /trends correlation table), the network group matrix, the /alerts outcome and severity tables, the /alerts/digest `<pre>`, and the two shared wrappers — `DataTable`'s scroller and `ChartTable`'s — which between them cover most tables in the app. Each takes `tabIndex={0}`, `role="region"` and a translated `aria-label`: the tabindex is what makes it scrollable, and a tabbable box becomes a landmark, so an unnamed one would be worse than none. Two new label keys carry the name (`a11y.scroll.table` / `a11y.scroll.panel`, plus three fixed labels for the shared wrappers and the digest); the heat matrix borrows its own `<caption>`. Deliberately NOT done: adding these selectors to the gate's allow-list. The one allow-list entry stays what it always was — the Leaflet and Cytoscape canvases, which have a declared table equivalent and are phase 9's row 134 — and it still matches zero nodes. Also fixed under the same rule: the heat-calendar month buttons (a per-cell `min-w-[24px]`, because the table's own min-width cannot hold the column open once the year and total columns size to their content) and the corridor traveller links (`py-[3px]`, so an 18-px line box clears the 24-px spacing test).

**D-phase5-14 · What is still red in the a11y gate on 29 Aug, and whose it is (team, 29 Aug 2026).**
The 68-audit sweep ends with 16 serious nodes, none of them this workstream's and none of them a rule that was disabled to go green. Twelve are `color-contrast` on /alerts in both themes and both viewports: `AlertCard` dims an acknowledged card with `opacity-80` and a snoozed one with `opacity-70`, and container opacity composites into the text — the slate Badge measures 4.10:1 (dark, #717A8D on #10182A) and 3.57:1 (light, #7A879C on #FDFDFE) against the 4.5 bar for 11-px text. The `.text-muted\/50…80` clamp in index.css cannot reach it, because the alpha is on an ancestor, not on the colour; the fix is a design call about how a settled alert should read, so it belongs with the contrast owner. The other four are `scrollable-region-focusable` on /station at 360 px — two wide tables in `Station.jsx`, a phase-4 file, needing exactly the one-line treatment in D-phase5-13. One latent hazard found while measuring and not fixed: the depth heat matrix paints its cells `rgba(245,166,35,α)` with α up to 0.68, and on the brightest cells even the full `--t-ink` label would measure about 3.2:1 in the dark theme — today's data never gets that hot, so axe does not see it, but the ramp, not the text colour, is the thing to change.
