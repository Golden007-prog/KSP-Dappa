# Round 2 · Phase 4 — decisions (officer tiers)

D-entries in docs/DECISIONS.md style, numbered D-phase4-N for the lead to renumber. Every fallback and judgment call in this workstream, with what the code actually returned.

**D-phase4-1 · The tier aggregates are computed in the API from CaseMaster / AggMonthly / StationRisk / HotspotCluster / AnomalyAlert, not from a new table (team, 28 Aug 2026).**
`GET /tiers/beat`, `/tiers/station` and `/tiers/state` (functions/dappa_api/lib/routes/tiers.js, registered in lib/app.js) derive every figure at read time over the existing ER tables, cached 300 s like the other read routes, and stamp `meta.provenance {asOn, window, method, provisional:true, tables}` on every answer in the Monthly Crime Review's own "provisional · as on" idiom. Why: the Round-2 ER schema is law and the Development Data Store already holds the rows; a materialised "tier" table would be a second source of truth that drifts. Measured through the stub harness: `/tiers/beat` 200 in 17 ms, `/tiers/station` 200 in 5 ms, `/tiers/state` 200 in 4 ms (functions/dappa_api/test/round2/phase4.test.mjs, 64 checks; the suite read 870 / 870 when this was the only Round-2 file and 1360 passed / 1 failed at hand-over, the one failure being `WIRED search sends the documented query shape` in test/run.mjs:1329 against lib/search.js — both files uncommitted edits of another workstream, not touched here). On the deployed Development API the route is not yet live — `curl …/api/v1/tiers/beat` returned `{"ok":false,"error":{"code":"NOT_FOUND","message":"No route for GET /api/v1/tiers/beat"}}` on 28 Aug 2026 — so the lead's deploy is the switch-on.

**D-phase4-2 · "Usual level" is a Poisson-floored mean, and a station with no history reads NO DATA, never STABLE (team, 28 Aug 2026).**
The beat's 7-day usual is the 12-month AggMonthly monthly mean divided by 365/12/7; the station's per-head usual is the mean of weeks 1–7 against week 8; the swing (z) divides by `max(spread, √usual, 1)`. A unit with no rows answers 200 with empty arrays and `statusWord:'nodata'` (pinned by the phase-4 suite with a synthetic empty station '1099'), because a three-cases-a-week station must not be told it is "three swings above normal" over one extra FIR, and an unscored station must not be painted green. Why: docs/UX_RESEARCH.md §11.1 rule 3 ("call noise noise") and the colour-discipline rule that a status word is a claim.

**D-phase4-3 · Status words are computed once, server-side, from one rule (team, 28 Aug 2026).**
`statusFromZ`: z ≥ 3 → rising, 2 ≤ z < 3 → watch, z ≤ −2 → falling, else stable, null → nodata; pendency: > 60 d rising, > 30 d watch; risk word high/elevated/normal → rising/watch/stable. The client's lib/status.js repeats the same thresholds for values it derives itself (SLA state, hotspot activity). Every StatusPill renders colour + glyph + word (▲ ● ✓ ▼ —) and prints black; amber is used only for WATCH; forecast bands and the tier-switcher frame use the primary blue (design correction 2).

**D-phase4-4 · The tier switcher is presentation, anonymous lands on District, and a `?tier=` link wins over storage (team, 28 Aug 2026; extends D-015).**
`TierSwitcher` writes `useTierStore.setTier` and navigates to `TIER_HOME[tier]?tier=…`; `TierEyebrow` performs the once-per-session `GET /auth/me` read (`useAuthTier` → `applyRole`) so a signed-in Catalyst role opens on its tier, and a stored switcher choice still wins. Nothing in the switcher grants a capability; the tooltip says so ("Demo asset: changes what is shown first and how it is worded, never what you may do"). Desktop placement: the topbar at ≥ 1280 px (compact labels, full labels and the "Tier" eyebrow at ≥ 1536 px) because at 1280 px with the sidebar open the existing chrome leaves ~240 px; on phones both controls sit at the top of the More sheet at 44 px. Between 768 and 1279 px the controls are reachable only from the sidebar routes and the `?tier=` link — recorded as a gap.

**D-phase4-5 · The Beat dismiss writes to the Phase-7 action log when an alert exists, otherwise to the phone, and always says which (team, 28 Aug 2026).**
`POST /alerts/:alertKey/actions` (lib/routes/actionlog.js) requires a dismiss `reason` from a fixed list, so the officer's free-text reason travels as `reason:'other'` + `note`, with `actorRole` = the current tier and `source:'tier-home'`; the primary "patrol tonight" action is recorded as a `note`. When the station has no open alert there is no subject key, and when the POST fails (offline, 4xx) the record is kept in `localStorage['dappa-tier-actions']` and the card shows "Saved on this phone only — the action log endpoint is not wired yet". A dismiss is never dropped silently. Not verified live: the Development API does not yet carry the Phase-7 route either (same deploy).

**D-phase4-6 · Offline beat card = last good answer in localStorage + a hand-written service worker; no Workbox (team, 28 Aug 2026).**
`Beat.jsx` stores the last successful `/tiers/beat` body per station and renders it when the query errors or `navigator.onLine` is false, with a "Saved copy from <time> · offline" pill (`role=status`). `client/public/sw.js` precaches the shell, serves navigations network-first with the cached index as fallback, static assets cache-first, and API GETs network-first with a 4 s timeout and a stamped last-good copy (`X-Dappa-Cache: saved <iso>`); it is registered only in production builds with `${import.meta.env.BASE_URL}sw.js`, so '/', '/app/' and the Pages base all resolve. Why two layers: the in-page copy works even where a worker is blocked (private mode, first visit) and the worker keeps the shell and every other GET. Icons: four PNGs drawn with Pillow from the favicon's shield (192/512, any + maskable). Not verified: install prompt on a real Android device; verified: the manifest parses and the build serves `sw.js` and `icons/*` from the public root.

**D-phase4-7 · Print per tier reuses index.css's print block plus one `@page` rule per tier (team, 28 Aug 2026).**
`tierPrint.jsx` injects Beat A5 portrait / Station A4 portrait / State A4 landscape, hides the Leaflet map (no tiles print usefully), drops tints, forces pills to black glyph + word and adds print-only "prepared for the <role> · <unit>" and glyph-legend lines. The provenance "method" became an inline disclosure (not a hover tooltip) so it reads on paper and on a phone. **D-phase4-8 · The static demo carries the three tier snapshots so GitHub Pages renders the tier homes (team, 28 Aug 2026).**
`scripts/demo_snapshot.mjs` snapshots `/tiers/beat`, `/tiers/station`, `/tiers/state`; the three files were also written into client/public/demo/api now (keys `get_tiers_beat.ddb8fa81`, `get_tiers_station.ea388e99`, `get_tiers_state.0cadb3ce`) and the Playwright walk against a `VITE_STATIC_DEMO=1` build rendered all four new routes at 360×640 and 1280×800 with no console errors: Beat 5 status pills, Station 12, State 48; every control on Beat / Station ≥ 44 px (0 under-size at 360). **D-phase4-9 · The fixture was NOT extended for the tier screens (team, 28 Aug 2026).**
The contract suite pins CaseMaster at exactly 40 rows in eight places (`/cases` totals, `/healthz` row counts, `/network/*` scans), so adding under-investigation cases for a richer Beat / Station fixture would have broken green checks owned by other phases. Consequence: in fixture / static-demo mode the Beat "my assigned cases", the Station "caseload" and "undetected > 30 d" panels show their empty states; on the Development Data Store (45,000 CaseMaster rows) they fill. The empty states are real states, not placeholders.

**D-phase4-10 · Tooltips on the tier homes wrap; the app's CSS tooltip is nowrap (team, 28 Aug 2026).**
`.tt::after` in index.css is `position:absolute; white-space:nowrap; opacity:0` — an invisible tooltip still widens the page's scroll area, and a glossary sentence behind a 44-px (i) measured 700 px of horizontal scroll on a 360-px phone. `tierPrint.jsx` scopes `.tier-home .tt::after { white-space:normal; max-width:min(300px,78vw) }`; after the change the tier routes report the same 390 px scroll width as every other route at 360 px (a pre-existing 30 px overflow that is not this phase's — flagged to the lead).
