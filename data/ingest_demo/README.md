# data/ingest_demo — the twenty-second ingest demo

`CaseMaster_sample.csv` holds **200 rows** in the official ER column order (docs/SCHEMA_CHECKLIST.md §20) plus two extra columns the privacy guard must catch (`Caste`, `ComplainantPhone`). It is generated by `node scripts/make_ingest_demo.mjs` from `pipeline/out/CaseMaster.csv`:

- 183 clean rows from 2026-07 (the latest month in the pipeline output) in districts whose synthetic coordinates all fall inside their census polygon, renumbered to CaseMasterID 90001+ and CrimeNo serial 90001+ so a load never duplicates the 45,000 rows already in the Data Store.
- 17 deliberately special rows — 12 rejected, 5 accepted with a note — so the rejection report and the privacy guard have something to show.
- The file starts with a UTF-8 BOM and uses CRLF line ends, the way Excel writes it.

| 19 | CrimeNo district segment 0136 (KGF) while the station belongs to another district | `CRIMENO_DISTRICT → rejected` |

Upload it at `/ingest` → table **CaseMaster** → auto-map → validate. Against the live Development Data Store the `DUP_IN_STORE` row is caught by the CrimeNo/CaseMasterID page reads; against the bundled fixture it is caught by CaseMasterID 1, which the fixture also holds.
